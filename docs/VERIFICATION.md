# Як перевірено Shop Assistant

Короткий підсумок для замовника. Повний журнал розробки й розгортань — у [docs/dev/VERIFICATION-LOG.md](dev/VERIFICATION-LOG.md).

## Автоматичні перевірки

| Перевірка | Що доводить | Результат |
| --- | --- | --- |
| `pytest` (Python 3.11 і 3.12) | Імпорт, пошук, картки, діалоги, звернення, заявки, медіа, шаблони, нагадування, робочі години, статистика, імпорт через бота, черга доставки, перезапуск, ліміти, бюджет LLM | 205 тестів проходять |
| Те саме без Anthropic SDK | Безкоштовна вітрина не залежить від платного розширення | Тести LLM пропускаються, решта проходить |
| `ruff check` | Стиль, імпорти, типові помилки Python | Без зауважень |
| `evals/free_run.py` | 40 реальних запитів до пошуку й підписи всіх 20 фотокарток | 40/40 запитів, 20/20 карток |
| `pip check` | Сумісність залежностей у середовищі й Docker-образі | No broken requirements found |

Автотести підміняють Telegram API. Вони покривають двох незалежних клієнтів, Reply через адаптер, закритого й невідомого адресата, чужу історію, перезапуск, статуси доставки й теми з повтором надсилання.

## Реальне середовище

- Docker-образ без root і без відкритих портів працює на VPS (ARM64) із named volume.
- Перед кожним оновленням робиться узгоджена копія SQLite; після оновлення звіряються кількість товарів, діалогів, звернень і тем.
- Справжній Telegram підтвердив назву бота, меню, категорії, фотокартки, пошук, довідку, кабінет менеджера й увімкнені теми.

## Що перевіряється вручну

Наскрізний сценарій «клієнт → менеджер → клієнт» потребує двох різних Telegram-акаунтів. Сценарій кроків описано в [DEMO.md](DEMO.md). Платний прогін LLM не входить у приймання безкоштовної вітрини: його порядок описано в [evals/README.md](../evals/README.md).
