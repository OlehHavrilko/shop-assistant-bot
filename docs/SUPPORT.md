# Обращения: кабинет и отдельные переписки

Причина изменения: владелец проверил бота с другом и сообщил, что обычный Telegram Reply не доставляет ответ. Адаптер не передавал `reply_to_message.message_id`, поэтому такой текст обрабатывался как запрос к каталогу. Прежний `/tickets` показывал только номера, а историю обращения нельзя было открыть.

## Интерфейс

- Менеджер: `/start` → общая витрина магазина с дополнительной кнопкой «Кабінет менеджера» → активные обращения → «Відкрити діалог». Внутри — контекст товара, история с датами, ответ обычным сообщением и завершение с подтверждением. Есть архив и страницы истории. `/tickets` открывает кабинет напрямую; `/help` возвращает витрину. Возврат к списку или витрине снимает выбор адресата в обычном чате.
- Telegram «Ответить»: адресат определяется по ID действительно отправленного ботом сообщения, сохранённому в outbox. Выбор другого обращения не подменяет адресата. Неизвестный или закрытый адресат вызывает подсказку, а не отправку другому клиенту.
- Клиент: уведомление о передаче, переписка, «Моє звернення» с историей и завершение с подтверждением. Каталог доступен кнопкой. В обычном чате текст при открытом обращении адресован менеджеру; в режиме тем каталог остаётся в основной переписке, разговор с менеджером идёт в теме обращения.
- Статус в истории менеджера: ожидает отправки, доставка задерживается с повтором, принято Telegram. Последний статус не означает прочтение клиентом. Команды `/reply НОМЕР текст` и `/bot НОМЕР` сохранены.

## Настоящие отдельные темы

1. В настройках этого бота в BotFather включить **Threaded Mode**. Темы обращений создаёт приложение. Темы, созданные пользователем, также поддерживаются для каталога: они не считаются обращениями, пока не зарегистрированы в `support_topics`. Нужна актуальная версия клиентского Telegram.
2. После изменения перезапустить один экземпляр сервиса. При старте он читает `getMe.has_topics_enabled` и пишет в лог только булево состояние режима, без токена или ID.
3. При первой доставке создаётся тема «Звернення #N» отдельно в чате клиента и в чате менеджера. Соответствие `(chat_id, ticket, message_thread_id)` сохраняется в SQLite. Ответ в теме маршрутизируется по ней; выбор в основном меню его не переопределяет.
4. Основной чат используется для витрины и списка обращений. Закрытая тема сохраняет историю, но приложение не пересылает из неё новые сообщения. Повторное обращение получает новый номер и новую тему.

Бот не может самостоятельно включить этот параметр BotFather. Если он выключен, отдельные темы не создаются: работает кабинет с выбранным диалогом и Telegram Reply. Ошибка создания темы не выдаётся за доставленный ответ: очередь сохраняется для повтора. После удаления темы, обнаруженного при отправке, привязка сбрасывается и при повторе создаётся новая тема. При неоднозначном сетевом сбое создания возможна лишняя пустая тема; существующая граница at-least-once доставки также сохраняется.

## Данные и проверка

Миграция схемы диалогов v1/v2 → v3 добавляет историю, контекст обращения, выбор менеджера, темы и Telegram ID доставленных сообщений. Существующие каталог, обращения и очередь не удаляются. Для текущих старых обращений переносится сохранённый контекст; полной отдельной истории, которой раньше не было, миграция не восстанавливает. Перед установкой на VPS нужна согласованная резервная копия SQLite по `DEPLOYMENT.md`.

Автотесты покрывают два независимых клиента, Reply через адаптер и очередь, закрытый/неизвестный адресат, чужую историю, перезапуск, статусы доставки, пагинацию и темы с повтором отправки. Telegram API в них подменён. Приёмка в реальном Telegram: два клиента создают обращения; менеджер отвечает в обе темы, затем через Reply; оба проверяют адресата. После перезапуска повторить ответ и завершить одно обращение, сохранив другое. Проверить внешний вид основного чата и тем на используемом Telegram Desktop.

## Основания решения

- [Telegram-shop: Main menu](https://github.com/interlumpen/Telegram-shop#-feature-tour) — общий главный экран магазина с дополнительной административной кнопкой для соответствующей роли. Витрина доступна менеджеру сразу; кабинет не заменяет её.

- [Chatwoot: Telegram support inbox](https://www.chatwoot.com/features/telegram-integration) — пример отдельного рабочего интерфейса менеджера с историей диалогов. Сам Chatwoot в проект не добавлен.
- [Telegram Support Bot](https://github.com/bostrot/telegram-support-bot) — реальный открытый проект с обращениями и ответом сотрудника обычным Telegram Reply; использован как ориентир поведения, его код и инфраструктура не перенесены.
- [Telegram: topics in private chats](https://core.telegram.org/bots/features#topics-in-private-chats) — нативное разделение переписки на темы.
- [Bot API: createForumTopic](https://core.telegram.org/bots/api#createforumtopic), [User](https://core.telegram.org/bots/api#user) и [Message](https://core.telegram.org/bots/api#message) — создание тем, определение режима, идентификаторы темы и Reply.

## Темы витрины

Ответы каталога остаются в исходной пользовательской теме. Неявный Reply на служебное сообщение `forum_topic_created` игнорируется адаптером; настоящий ручной Reply по-прежнему проверяет сохранённого адресата. Закрытые темы обращений не становятся темами каталога.
